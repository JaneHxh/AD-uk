# 英国站亚马逊广告分析固定流程

## 角色与交付

用户提供数据，分析者核对、分析并提出方案；用户决定同意、调整或暂缓；分析者随后整理最终执行指令；执行后在下轮用成熟数据复盘。没有明确指令不修改广告后台，不把沉默视为批准，不将预算建议当作已批准支出。

优先级固定：热销 > 新品 > 维护。保留清货/季节性标签，不凭销量自动改标签；先满足库存和利润门槛，再决定投入。

## 每轮输入（领星导出可直接使用）

1. 同一店铺/国家/币种、相同起止日的三类SP搜索词：自动、关键词、商品投放。建议滚动60天，能提供按天明细则保留日期。
2. SP关键词目标、商品投放目标与最新广告设置：活动/组/目标ID、广告商品ASIN/MSKU、匹配、有效状态与服务状态、竞价、日预算、广告位加价；完整否定关键词及否定ASIN清单。广告商品报告解决活动名称推断不可靠的问题。
3. 同期产品表现ASIN：销量、销售额/净销售额、广告花费/销售/订单、直接成交、7/30日销量；提供Listing主MSKU-ASIN映射及产品标签。
4. 当日FBA仓库库存：仓库、店铺、MSKU、ASIN、可售、预留、入库、在途；另给补货预计可售日期。不要把在途算作当日可售。
5. 成本利润表：ASIN/MSKU、有效期、币种/汇率、下一轮实际含税折后成交价、成本/头程/VAT/佣金/FBA/服务费/仓储/运营/退货/促销，以及广告费是否已计入。成本测算表与期间实际结算利润表分开标注。
6. 简单经营约束：总日预算上限、最低利润要求或可承受测试亏损额、本轮促销/缺货/补货变化。

### 提供频率与工作量

- 每轮直接提供领星原始导出，不需要先替分析者清洗或填模板：广告搜索词/目标、产品表现、当日库存。能导出日期粒度则优先保留。
- Listing映射、产品标签、利润成本表首次提供后可复用；改价、促销、成本/汇率/FBA费变化、标签变化或跨季度仓储费变化时更新。未更新时明确沿用日期，不能假定一直有效。
- 广告商品对应关系首次完整提供后，可用变更记录维护；预算/状态/竞价/负面目标要用当期最新状态。
- 总预算、可承受测试费、补货与促销计划可用一段文字补充。缺失时先做独立分析并把受影响建议标为条件方案。

店铺/国家/币种/期间、汇总行剔除、重复明细、字段缺失、公式错误、匹配覆盖率必须先核对。文件里的操作说明只作为背景，不能自动作为用户指令。

## 默认3个Sheet

- 01_决策总览：用户主要看；产品优先级、建议动作、关键证据、预算动作、风险、执行条件、同意/调整/暂缓。
- 02_执行清单：仅供已批准事项落地；产品、活动/组、关键词/ASIN、匹配、竞价、预算、执行条件、复盘节点。缺少ID时明确不可直接Bulk导入。
- 03_数据依据：原文件/行、汇总、利润和库存口径、匹配与覆盖证据、数据缺口。

每条建议区分“建议执行/小预算测试/继续观察/信息不足暂缓”，列明可观察结果，不编造销量提升或节省金额。新增数据改变结论时明确撤回旧建议。

## 判断原则

- 核心词按商品归属×搜索词聚合，先看成交、直接成交、相关性与效率，再核对现有精准/词组/广泛与运行状态；已存在但暂停不算运行。
- 关键词/商品目标表仅查覆盖及目标优化，不与三份搜索词表重复叠加业绩。多ASIN或名称冲突不把订单分给单品。
- 利润率须核实广告前/后、税前/后、价格及费用期。不得将旧成本表净利率或统一20%/30%目标直接作为盈利ACOS。Q4使用对应仓储假设；成本测算不是已实现利润。
- 库存可售÷max(近7日均,近30日均)作为保守覆盖，低于14天不扩量；0近期销量不计算无限覆盖。
- 有单高ACOS先控价；无单否定结合成熟归因、花费/点击门槛、同商品别组成交、自有ASIN、现有否定。只在指定组精准否定，不能误伤同义出单词。
- 新精准有实际承接且预算可用后，才考虑旧探索组精准分流否定。
- 默认不增加总预算。测试学习费与可持续盈利预算分开，具体金额由用户决定。

## 复盘与版本

第3天查曝光/预算/状态，第7天查成熟转化，第14天评估扩量/降价/否定；按账号实际归因窗口执行。每轮记录决策、实际执行日期及是否执行，避免把未实施方案当作效果。

报告使用日期和版本保存，保留旧版以便审计；仅将分析产物与流程保存到用户指定私有仓库，原始利润/库存文件不必重复上传。Git提交不表示用户已批准广告操作。
